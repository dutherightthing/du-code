# References

Learning inputs for the harness — annotated notes on past projects, so agents can pull real context and patterns from what Jerry has already built (and what went right/wrong), the way `du-design`'s references hold annotated past work.

## What goes here
- `past-projects/` — one short markdown note per notable project: what it was, the stack, what worked, what broke, what you'd do differently. Point to the real repo; don't copy code in.
- Patterns worth reusing across projects (a scraping pattern, an email-sending setup, a deploy flow).

## How agents use it
During **Scope** and **Plan**, skim relevant references — if Jerry's done something similar before, reuse the approach instead of reinventing it. During **Capture**, add or update a note.
